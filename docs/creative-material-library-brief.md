# 启动 Brief：差异化创作素材库的质量审计与轻量结构化

## 1. 任务目标

为 Emochi 创作 Agent 建立一套**轻量、可被 Agent 按需参考的差异化创作素材库**。它的目的不是回答事实问题、复刻原始世界书或搭建重型 RAG，而是减少 Bot 创作对高频训练语料、常见题材拼接和泛化人设模板的依赖。

你需要完成两件事：

1. **粗略评估给定数据的质量和可用性**：哪些内容适合转化为创作素材，哪些必须排除、限用或仅保留为来源；
2. **把可用内容设计并初步转换为可入表的结构化素材单元**：支持后续“无主题随机灵感”和“有主题的轻量参考”两种场景。

本任务追求可用、可审阅、可迭代；**不要把它做成生产级知识图谱、向量数据库或复杂 RAG 系统**。

## 5. 建议的目标形态（可调整，但不要无故复杂化）

### 5.1 两层数据，而非直接把整个世界书塞入一张表

建议保留：

```text
来源层（Source）
→ 用于追溯原始帖子/文件；不作为日常 Agent 注入内容

创意素材层（Creative Material）
→ 短小、可再创作、可组合的素材单元；未来 Agent 实际使用
```

不建议：

```text
一个完整世界书文件 = 一个素材行       # 过粗
每个原始 entry 一律 = 一个素材行       # 过碎、噪声和长度不均
将全部原文直接塞给 Agent               # 上下文重、风险高、易照搬
```

### 5.2 候选最小表结构

以下只是推荐最小集；允许因真实数据做小幅修改，但不要增加大量“看起来完整”的字段。

```ts
type CreativeMaterial = {
  id: string;
  source_id?: string;
  source_entry_id?: string;

  title: string;
  material_type:
    | "character"
    | "relationship"
    | "world_rule"
    | "setting"
    | "scene"
    | "conflict"
    | "narrative_device"
    | "interaction_mechanic"
    | "style_detail";

  content: string;
  summary?: string;
  tags?: string[]; // 少量、受控，不做无限标签体系

  safety_status: "usable" | "restricted" | "excluded";
  enabled: boolean;
};
```

可以补充一个非常小的来源表，例如：

```ts
type MaterialSource = {
  source_id: string;
  title: string;
  source_file?: string;
  source_url?: string;
  source_type: "lorebook" | "text" | "other";
};
```

### 5.3 素材类型的判断标准

`material_type` 是**素材在创作里能发挥的作用**，不是原始帖子的目录标签，也不是 Bot 字段分类。

| 类型 | 典型内容 |
| --- | --- |
| `character` | 欲望、矛盾、身份错位、行为限制、独特反应模式。 |
| `relationship` | 双方目标、秘密、依赖、误解、权力或信任结构。 |
| `world_rule` | 改变“什么可发生/不可发生、谁能利用、代价是什么”的规则。 |
| `setting` | 具有互动职责的地点、组织、资源、制度或环境。 |
| `scene` | 可直接进入、有压力和行动空间的场景装置。 |
| `conflict` | 可持续推进、但不替用户锁死结局的冲突。 |
| `narrative_device` | 信息差、叙事视角、秘密、时间、身份或结构性反转。 |
| `interaction_mechanic` | 用户行动、反馈、代价、替代路径或持续循环。 |
| `style_detail` | 可提升质感的生活、感官、表达或观察细节；不能只是空泛文风词。 |

## 6. 处理规则与质量边界

### 应优先保留/提炼

- 能改变角色选择、关系发展、信息流动、行动代价、叙事压力或互动反馈的设定；
- 有明确可改写价值的世界规则、关系机制、冲突装置、场景入口、玩法循环；
- 能让 Bot 更具体、更有辨识度、同时不封死用户行动空间的细节；
- 内容本身可被压缩为一张短“设定卡”，并能用自己的语言再创作。

### 应排除或不自动入池

- 明确的未成年人、性化未成年人、非自愿/违法成人内容、剥削、性暴力、极端残虐等；
- 成人性癖/露骨文风/性行为细节，不应进入通用随机池；
- 仅适用于旧平台的正则脚本、变量表、状态栏、自动触发、前端 UI 配置；
- 大段 IP/同人设定原文、角色卡原文、可识别作品内容；
- 没有可迁移创意价值的提示词、质量词、格式模板或纯运行时配置；
- 只是高频套路、换职业/换名字的空壳人设，或无法说明它如何改变互动体验的内容；
- 空 entry、分隔标题、禁用条目、纯目录条目。

### 长文本切分

- 不使用机械固定长度分块作为最终素材粒度；
- 短且语义完整的内容可以保留为一个素材单元；
- 较长 entry 应按语义职责拆分为少量单元，例如世界规则、组织/地点、关系机制、冲突、互动入口；
- 每条入表素材应尽量短、独立、可读；不要带入原始触发关键词、注入顺序、概率、正则等运行时字段；
- 不要照搬原文。对外使用/入素材表时应做概括、匿名化、转述和可再创作改写。

## 7. 两种使用场景的最低支持要求

### 场景 A：无指定设定，获取灵感

无需语义检索或重 RAG。建议：

```text
从 enabled + usable 的素材池中抽取 1 条
```

可采用简单的类型均衡：先选 `material_type`，再从该类型随机选一条，避免样本量大的类型垄断结果。

返回给 Agent 的素材应是“启发”，不是要求直接采用。Agent 应结合当前用户请求进行改写、组合或反转。

### 场景 B：有指定主题或已有内容，需要参考创意

不做向量库。建议先用轻量规则：

```text
当前 Skill 领域
+ material_type
+ title / summary / tags 的关键词轻匹配
+ 少量随机性或多样性抽样
→ 返回少量候选（例如 1–3 条）
```

例如世界观/剧场任务优先抽 `world_rule`、`setting`、`conflict`、`narrative_device`；角色任务优先抽 `character`、`relationship`；玩法任务优先抽 `interaction_mechanic`。

不要因用户主题词没有精确命中就返回空结果；允许保留一条跨域但有启发价值的素材。
