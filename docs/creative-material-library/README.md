## 3. 最终入表数据模型

两层结构：**CreativeMaterial（素材层，Agent 使用）+ MaterialSource（来源层，仅追溯）**。

```ts
type CreativeMaterial = {
  id: string;                    // 必填
  source_id?: string;            // 选填
  source_entry_ids?: string[];   // 选填，仅内部追溯
  title: string;                 // 必填
  material_type:                 // 必填
    | "character" | "relationship" | "world_rule" | "setting" | "scene"
    | "conflict" | "narrative_device" | "interaction_mechanic" | "style_detail";
  content: string;               // 必填，改写后的设定卡
  summary?: string;              // 选填
  tags?: string[];               // 选填，受控标签 1–4 个
  safety_status: "usable" | "restricted" | "excluded";  // 必填
  enabled: boolean;              // 必填
};

type MaterialSource = {
  source_id: string; title: string; source_file?: string; source_url?: string;
  source_type: "lorebook" | "text" | "regex" | "character_card" | "mvu" | "other";
  category?: string; nsfw_level?: string; nsfw_entry_counts?: Record<string, number>; note?: string;
};
```

字段取舍、`material_type` 判定标准与 v1 相同（见 git 历史 / 上文）。核心：不做 embedding、不做全量标签体系、不保存原文快照、不保存运行时字段。

## 4. 长文本切分与改写规则

1. 不用固定长度机械分块；短且语义完整的内容整条保留。
2. 长 entry 按**语义职责**拆为少量单元（规则/地点/角色/冲突/入口）。
3. 每条素材短、独立、可读（1–4 句）。
4. 不搬运原文：概括、匿名化、转述、去 IP、去露骨、去运行时字段。
5. 拆分保留 `source_id + source_entry_ids` 追溯。

### 4.1 切片（分块）决策

| 情况 | 要不要切 | 怎么切 |
|---|---|---|
| 短且单职责（≤ ~500 字） | 不切 | 整条改写 |
| 长但单职责（规则+示例） | 不切 | 改写压缩 |
| 长且多职责（规则+地点+角色+事件混排） | 切 | 语义拆 2–5 个单元 |
| 含运行时字段 | 先剥离再切 | 删字段后按语义切 |
| 露骨 NSFW 混入长文本 | 切+排除 | 保留 SFW 机制段，露骨段丢弃 |
| 长但完全可用（>5000 字，规则/设定密集型） | **切（不排除）** | 按语义职责拆 2–10 个单元；总控确认长条目可用，只是要切片 |

判定顺序：`禁用/空 → NSFW 露骨段 → 运行时字段 → 单职责？ → 整条 / 剥离后整条 / 语义拆分`。切片在改写阶段做，不是对原文做字符切割。

## 5. 两种使用场景的选择/抽样逻辑

### 场景 A：无指定设定 → 随机灵感
1) `enabled=true` 且 `safety_status=usable` 池；2) 按 `material_type` 类型均衡；3) 类型内随机 1 条；4) 返回的是“启发”，需结合用户请求改写/组合/反转。

### 场景 B：有指定主题 → 轻量参考（1–3 条）
1) Skill 领域映射类型集合（世界观→world_rule/setting/conflict/narrative_device；角色→character/relationship；玩法→interaction_mechanic/world_rule/conflict）；2) title/summary/tags 关键词轻匹配；3) 未命中时保留 1 条跨域启发，绝不返回空；4) 少量随机/多样性抽样。

## 6. 刻意不做的事与理由（不上 RAG）

| 不做 | 理由 |
|---|---|
| 向量库/Embedding/RAG | 语料脏且规模小；轻量关键词+类型均衡已够用 |
| 全量 26,838 条入表 | 过碎、噪声高、IP/NSFW 污染 |
| 整本世界书=一行 | 过粗 |
| 大而全标签体系 | 维护成本高 |
| 保留触发词/注入参数/概率/正则 | 平台绑定 |
| 原文快照/全文注入 | 版权与照搬风险 |
| 素材推荐写成自动改 Bot | 素材库是只读参考层 |

## 10. 验收问题自答

- 一条素材=可独立复用、可改写/组合/反转的最小创意单元（设定卡）。
- 粒度：短于整条长 entry、长于机械分块；干净池中位 390 字。
- 无灵感时：类型均衡 + 类型内随机，1 条启发，无 RAG。
- 有主题时：Skill 领域 → 类型映射 → 关键词轻匹配 → 保底 1 条跨域，1–3 条。
- 防复制/污染：改写规则 + safety_status 闸门 + enabled 开关 + 永不注入原文。
- 扩展性：字段稳定，加数据只追加素材行，加 Skill 只改类型映射，加前端只消费 title/summary/tags/material_type。

## 11. 打标签（tagging）可行性——好不好打？

**结论：好打，但要控制词汇表。**

1. 37 条样本已带 tags（1–4 个/条，去重后约 30 词）。

4. 反模式：不为每条发明新标签；不打来源/作者/平台标签；先切片再打标签。

### 12.3 数据来源与转述原则
- 来源：早期 37 条样本改写 + 37 条高价值文件新改写（curated）；再以全量可用池非 IP 候选生成 1,884 条 auto（机器预标注 + 压缩转述，需复核）。`sources.json` 已扩到 26 个来源。
- 所有 `content` 均为**概括/转述/匿名化**的设定卡；IP 内容（拔刀剑概念锻造、奥特曼巨型规则、神明级魔法、宝可梦图鉴等）已**抽象为无专属名词的机制/结构**（如“概念锻造”“巨型单位物理”“关键字即咒语”）。
- 不复制大段原文；来源字段只保留内部追溯。

### 12.4 长文本提取原则
- 长 entry 仅在有**独立可复用机制**时按语义职责提取（规则/关系/地点/冲突/入口），如“三层传播”“任务分层与每日衰减”“圣钢与地狱金属的代价”。
- 不使用固定字符数机械切块；>5000 字的 73 条清单见 `slice-plan.json`，本次只取其中可独立成卡的机制部分。

### 12.5 Tag 规则
- 两个维度正交：`genres`=外层题材/体验，`material_type`=内容作用；二者不可互相替代。
- 不再使用自由 `tags` 数组；genres 受控 0–3 个、material_type 恰好 1 个。
- 方法论型素材（人设/写作方法，5 条）允许 `genres=[]`，统计见 `tag-distribution.md`。
