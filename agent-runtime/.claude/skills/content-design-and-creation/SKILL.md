# 内容设计与创作

## 职责

本 Skill 负责把零散想法或已有内容推进为当前阶段应有的交付：完整候选、蓝图、内容设定或最小修改。它统筹体验、内容和范围，不以填满设定、输出长文、自动创建 Bot 或自动保存过程数据为目标。

角色、世界、剧场、玩法出现深度专项问题时协作对应 Skill。只要本轮目标是产生新方向、补充、重写或修改，均由本 Skill 统筹；纯审查的路由由独立的审查 Skill 处理，不在此处重复判断。

## 工作流

本 Skill 负责决定这一轮如何从意图走到可审阅交付，再在明确授权后进入业务动作；专项 Skill 只负责把角色、世界、剧场或玩法的某个维度设计好。

```text
1. 定位本轮目标
   → 探索新方向 / 展开未来新 Bot / 修改明确已有 Bot。
   → 有已有 Bot 时，先读取受影响区域；没有时，不假设已创建 Bot。

2. 判断交付深度
   → 方向未定：形成 1–3 个完整候选。
   → 方向已定、需要展开：读蓝图或正文方法并产出对应内容。
   → 已有 Bot 的局部问题：形成最小明确差异。
   → 若触及体验承诺、核心关系、世界规则或玩法原型：回到候选/蓝图层重新收束，不直接局部修补。

3. 补齐必要维度
   → 只为当前缺口读取角色、世界、剧场、玩法等专项 Skill。
   → 需要灵感、反套路切口或某一维度补充时，可按需使用 creative_material_search。

4. 形成可审阅交付
   → 新创作候选包含体验承诺、用户位置、独特核心、持续张力与首次进入。
   → 整体创建或整体修改时，同步检查名称、简介、欢迎语与核心内容。

5. 进入业务动作
   → 仅在用户明确创建或确认修改后调用 bot_workspace.create / bot_workspace.update。
   → 否则方案保留在对话中，不自动创建 Bot、Artifact 或图片任务。

6. 写入后核对
   → 核对结果覆盖预期区域、保留已确认核心，并让当前 Session 绑定目标 Bot。
```

新创作请求已有有效信息时，直接给出 1–3 个完整互动候选，不把候选内容拆成连续 Choice。只有存在无法从现有输入推断、且会实质改变体验的 2–3 个方向时，才按全局规则让用户选择；其余细节主动补全。

## 默认展示与开场规则

名称、简介与欢迎语属于完整创作或整体修改的默认交付，应与核心内容一起检查；不需要为此单独建立一轮问答。

```text
名称：让我一眼识别对象、世界或关系入口。
简介：让我想点开。
欢迎语：让我立刻知道正在发生什么，以及能如何回应。
内容设定：让模型在之后持续把互动做对。
```

- **名称**应清楚、可记住，优先对象、世界、关系或独特切口；不要堆职业和形容词。
- **简介**的目标是吸引点击，而不是完整说明设定。保持短、可快速扫读；根据题材自由选择最有吸引力的一个切口，例如人物魅力、关系张力、反常设定、秘密、风险、用户处境，或自由进入/创造故事的体验承诺。不要机械套固定结构，也不要复述世界观、角色档案或玩法清单。
- **欢迎语**从已经发生、且需要用户回应的异常、压力或机会开始。先给事件、角色/环境反应和用户位置，再补最少必要背景。用户必须处在事件关系网中，能解释、追问、选择、阻止、谈判、拒绝、离开或承担后果；不能只是旁观角色表演。
- 需要措辞灵感、比较不同展示切口或实际写 `basic` 时，读取 [`presentation-and-welcome-examples.md`](references/presentation-and-welcome-examples.md)。其中的案例只用于学习长度、信息密度和进入方式，不是固定模板。

## 判断与 Reference

先判断是否有明确的已有 Bot 目标；没有时可自由探索或面向未来新 Bot 创作，但都不代表立即创建 Bot。按当前交付读取必要 Reference，不要一次加载全部。

| 当前任务 | 读取 Reference | 使用原则 |
| --- | --- | --- |
| 形成或重构核心方向 | [`blueprint-design.md`](references/blueprint-design.md) | 候选/蓝图阶段读取。 |
| 将已确认方向落为 Bot 正文 | [`detailed-content-writing.md`](references/detailed-content-writing.md) | 仅在需要完整正文时读取。 |
| 修改已有 Bot 内容 | [`bot-update.md`](references/bot-update.md) | 仅在有明确现有 Bot 且本轮要改动时读取。 |
| 实际写名称、简介或欢迎语，需要表达参考 | [`presentation-and-welcome-examples.md`](references/presentation-and-welcome-examples.md) | 学习高密度展示与开场写法；不照抄案例。 |

当前创意过泛、缺少明确维度，或诊断到同质化/互动缺口时，可按需调用 `creative_material_search`，自行取少量素材并改写、组合或反转为候选、内容或最小差异；不直接拼贴、不将检索参数变成 Choice，也不自动写入 Bot。

## 分支验收

- **自由探索 / 新 Bot 创作**：用户获得可继续讨论或落地的方向；只有明确创建时才建立 Bot。
- **修改已有 Bot**：解决当前问题、保留已确认核心、给出最小明确差异，不扩大为整体重写。

交付前检查体验、进入、持续、用户行动空间、创新性、丰富度、自洽性、Prompt 可执行性与范围控制。

## 本领域边界

- 不通过额外 LLM loop 先做意图分类；依据本轮 Query、对话轨迹和最新 Bot Snapshot 判断。
- 蓝图、方案、普通回复、图片候选、Todo 和审查过程默认留在对话轨迹；不得因其“可能有用”自动创建 Artifact 或 Bot 更新。
- 涉及 Bot 搜索、读取、创建、更新或工作对象时，使用 `bot_workspace`；不得绕过 Tool 直接改 Bot。需要右侧可编辑工作页时才使用 `artifact_workspace`。
- 不定义聊天组件 payload、前端状态、图片轮询或 Tool 实现细节；不展示内部推理、工具执行过程或未完成草稿。
